# 寵物/兔子行為識別模型提升方案

## 現狀問題

**一句話：訓練數據和部署環境不一樣，模型骨架也太小了。**

- 訓練數據主要來自手持/網路影片，部署在固定攝影機畫面——視角、光線、背景完全不同，模型到現場「水土不服」
- 當前模型（RepViT-M1）是**為低功耗設備設計的輕量級架構**，PC 端算力相对充裕，但模型能力沒充分利用

---

## 改進方案：雙線推進

### 線一：數據

**做什麼：** 從深水埗和 hkbr 兩個實際部署點回收真實攝影機影片，補充到訓練集。

**重點加強兩個類別：**

貓狗數據集當前標籤分布：

| 類別              | 訓練集  | 驗證集 | 合計   |
| --------------- | ---- | --- | ---- |
| Other（移動/休息/跳躍） | 3117 | 779 | 3896 |
| Eat（進食）         | 745  | 137 | 882  |
| Drink（飲水）       | 705  | 126 | 831  |

兔子數據集當前標籤分布：

| 類別           | 訓練集  | 驗證集 | 合計   |
| ------------ | ---- | --- | ---- |
| Eating（進食）   | 1229 | 300 | 1529 |
| Moving（移動）   | 756  | 186 | 942  |
| Resting（休息）  | 899  | 220 | 1119 |
| Drinking（飲水） | 984  | 239 | 1223 |

貓狗Eat 和 Drink 兩個類別在實際場景中最關鍵，但在兩個數據集中樣本量都相對偏少，且現有數據以手持/網路影片為主，與攝影機實景差距最大。補充重點集中在這兩類。

**目標數據量：** 貓狗的 Eat + Drink 各從現有約 700 條補充至 1500 條以上；兔子的 Eating + Drinking 在現有基礎上各追加約 500-800 條真實攝影機數據

**同時給舊數據做處理：** 模擬攝影機畫質（運動模糊、解析度降低、色彩偏移），讓舊數據風格更貼近部署場景。

**耗時：** 數據採集和標註約 1-2 週（加interns），數據增強改造1-2天能做完

---

### 線二：模型 —— 「換粗一點的骨架」

**做什麼：** 把模型從 RepViT-M1 升級到 RepViT-M1.5，參數量翻倍（~5M → ~13M），但同屬一個架構家族，代碼改動小。

**額外加一個優化：** 給 backbone 加 TSM（可以理解成讓模型在看單幀的同時，自動參考前後幾幀的運動資訊），對識別「往前倒水」「歪頭吃食」這類動作更有幫助。

**耗时：** 模型改造約 2 天，重新訓練約 4-5 天（含調參迭代）

---

## 時間線

| 階段      | 內容                     | 預估時間  |
| ------- | ---------------------- | ----- |
| 第 1 週   | 數據回收 + 模型升級改造並行跑       | 3-5 天 |
| 第 1-2 週 | 用舊數據先訓練 M1.5 模型（不等新數據） | 2-3 天 |
| 第 2 週   | 新數據到位後，合併訓練最終版         | 3-5 天 |
| 第 2-3 週 | 部署驗證、根據線上回饋微調          | 3-5 天 |

整體 1-3 週完成各階段改造和驗證。

---

## 後續擴展

PC 端模型穩定後，可以用 PC 版模型作為教師（Teacher），重新蒸餾一個更小的版本來部署到低功耗設備（SoC），不需要重新採集數據。

---

## 需要的資源

1. 深水埗和 hkbr 部署點的錄製影片回撈
2. eating / drinking 類別的人工標註或半自動標註
3. 一台帶 GPU 的訓練機器（現有即可）
