VLM 標註可調參數清單

除修改 Prompt 與更換模型（Qwen3-VL 8B / 32B）之外，可影響或優化標註效果的全部參數，依影響層級分類。
鏈路：watchdog.bat → scripts/vlm_label/run_overnight.py → scripts/vlm_label/vlm_label.py 　·　整理日期：2026-10-09
⚠ 前置注意：run_overnight.py 的 run_label() 目前只透傳 --limit / --prompt / --yolo-* / --min-duration 等少數參數； --window-sec / --stride-sec / --frames / --max-side / --max-new-tokens 並未透傳。若要透過整夜編排調整這些參數，需先在 run_label() 補加對應參數，或直接呼叫 vlm_label.py。

一、輸入側參數Input — 決定模型「看到什麼」，影響最大

這一層直接改變送進模型的視覺證據，是細粒度行為（eating / drinking 嘴部動作）判別的第一槓桿。

參數預設值影響說明建議調法影響等級修改位置
--yolo-crop
--yolo-expand
--yolo-conf		 關閉 / 2.0 / 0.3 先以 YOLO 裁出兔子區域再推理，去除干擾源（另一隻兔、籠子、雜物）；expand 越小越聚焦動物本體、越大越保留場景上下文；conf 過低可能裁到誤檢框。未檢出時回退全幀。 crop 對照輪已在跑；expand 可試 1.5（更聚焦嘴部動作）vs 2.5（更多上下文）。 高 CLI（已透傳）
--max-side 448 長邊解析度上限。eating / drinking 的嘴部接觸證據非常小，448 px 可能不足以分辨；提高解析度可改善細粒度判別，代價是 visual token 增多、推論變慢、顯存佔用上升。 提到 640～768；先跑少量 clip 驗證 32B 的耗時與顯存。 高 CLI（未透傳）
--frames 8 單一窗口內的取樣幀數。更多幀 = 更密的時間證據，有助捕捉短暫動作；同時自動改變 Prompt 內的多數派閾值（n//2+1）。 8 → 12 或 16；幀越多越慢。 高 CLI（未透傳）
--window-sec
--stride-sec		 6 / 3 窗口幾何。窗口越長，單窗內行為混雜（mixed）風險越高；stride 越小重疊越多，相鄰窗口形成投票效果，時間線更平滑、片段更連貫。 試 4s / 2s（更細）或 8s / 4s（更穩）；stride 減半會使窗口數與耗時翻倍。 中高 CLI（未透傳）
TARGET / SCENE 佔位符 固定預設值 build_window_prompt() 支援注入場景描述，但主鏈路目前傳入 "none"。告知「水碗在左、草架在右」等真實場景資訊，可直接緩解 eating / drinking / grooming 的混淆。 程式碼級改動：在 make_prompt 傳入 scene 描述。 中高 vlm_label.py
--min-duration 0（crop 輪 0.5s） 過濾過短影片，避免單幀退化窗口產生噪音標籤。 依素材狀況按需設定。 低 CLI（已透傳）

二、解碼 / 推理側參數Decoding — 決定「怎麼生成答案」

此層不改變模型看到的內容，但影響生成行為與對照實驗的公平性。

參數 / 配置現狀影響說明建議調法影響等級修改位置
取樣策略 do_sample=False（貪心） 分類任務貪心解碼即為正確選擇，結果可復現；beam search 收益微小且顯著變慢。 不建議改動。 低 vlm_label.py
--dtype 8B = bf16
32B = bnb4 (NF4)		 混淆變數：目前 8B 與 32B 的效果差距中混雜著量化損失，並非純粹的模型能力差異。 加一輪 8B bnb4 對照，分離量化帶來的損失。 中 CLI（已透傳）
--max-new-tokens 512 僅防截斷與卡死，正常情況不影響標註品質；compact 模式每窗僅約 15 token，用不到 512。 維持即可；compact 模式可降低以加速失敗重試。 低 CLI（未透傳）
Processor 動態解析度
min_pixels / max_pixels		 未設定 Qwen3-VL 的 AutoProcessor 原生支援動態解析度控制，是 --max-side 之外的另一條解析度調節路徑，可精確控制 visual token 預算。 程式碼級：載入 processor 時傳入參數。 中 vlm_label.py

三、後處理側參數Post-processing — 不動模型，改「結果如何合成」

模型輸出之後的合成邏輯，直接決定最終時間線的形態與 Unknown 率，且零推論成本。

多數派規則 程式碼常量
n//2+1（8 幀需 5 幀）		 支持幀數不足即回 Unknown，是 Unknown 率的直接閥門：收緊 → 更多棄權、更高精度；放寬為簡單多數 → 更多具體標籤、更高召回。 先統計現有 Unknown 率，再決定放寬或收緊一檔做對照。 高 vlm_label.py 常量

四、建議試驗順序最划算的前四項

  1. --max-side 448 → 640
    細粒度動作識別最可能缺的就是解析度；若 32B 耗時可接受，這是首選試驗。
  2. --frames 8 → 12
    同一窗口內更多時間證據，有助捕捉短暫動作、穩定多數派判定。
  3. 多數派規則放寬一檔對照
    先看當前 Unknown 率有多高再決定；Unknown 過多會大幅增加複核負擔。
  4. YOLO --yolo-expand 1.5 vs 2.5
    確定 crop 的最佳視野：聚焦嘴部動作 vs 保留場景上下文的取捨。

五、執行注意事項

  • 換 tag、新目錄：每次對照實驗沿用現有慣例，改用新 tag（如 qwen3vl-8b-v5）寫入新文檔目錄，舊結果保持不動，審閱頁可直接加面板對比。
  • 顯存預算：max-side / frames 調大後 visual token 增多，32B NF4 的顯存餘量會被進一步擠壓（桌面 GUI 常駐約 2～5 GB）；改完先跑 5 條 clip 驗證耗時與是否 OOM，再放開跑全量。
  • 32B 不得設記憶體上限：bnb 4bit 拒絕 CPU 分派，帶 --gpu-mem-gib 上限會載入失敗，維持不設上限的全 GPU 放置（約 18 GB）。
  • 未透傳參數：調整 window-sec / stride-sec / frames / max-side / max-new-tokens 前，需先在 run_overnight.run_label() 補加透傳，否則改動不生效。
